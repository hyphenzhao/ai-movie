## P0-5 断点续跑：按指纹判断缓存（`scripts/run_pipeline.py`）

**问题**：`state.json` 只按步骤名缓存，改了 `TTS_FIT_MAX_SPEEDUP`、改了 `fit_segments_to_timeline` 的代码、
或重跑了上游 `tts`，下游 `fit` 都照旧"cached"；写文件也非原子，中途 kill 会留下截断的 JSON。

**改动**：每步记录指纹 `state["_fp"][step] = {input, cfg, code, files, up, extra, hash}`：
输入视频（大小/mtime/首尾 4 MiB 哈希）、该步读取的配置常量（`STEP_CONFIG`）、该步调用函数的源码哈希
（`STEP_CODE`，函数级而非模块级，改 `mix_audio` 不会让 `fit` 失效）、上游步骤指纹（`STEP_DEPS`）、
CLI 选项（`_args_extra`）。`Ctx.has()` 比对不一致即打印 `STALE (…)` 并重跑；`Ctx.save()` 写临时文件 + fsync + `os.replace`。
旧 state 无 `_fp` 视为有效；`--fp-adopt` 打指纹，`--fp-explain STEP` 解释，`--no-fp` 关闭。

**实测**：test_1 adopt 12 步后全部 cached；改 `--language en` → 只有 asr 报 STALE（`extra:language`）；
负载 JSON 与改动前逐字节等价（仅多 `_fp`/`_video`）。

## P0-2 全采样率立体声背景床（`demuxer.py`、`composer.py`）

**问题**：`demux_video` 只抽 16 kHz 单声道，分离与混音都在其上，`mix_audio` 以 background 采样率为准
→ 三部源片都是 48k/44.1k 立体声，成片却是 **16 kHz 单声道**。ducking 是逐采样二值门；配音电平与原片对白无关。

**改动**：
- `demux_video` 增抽 `audio_full.wav`（pcm_s24le，原采样率，>2 声道降为立体声）；`audio.wav` 命令不变，分析链路不受影响。
- `composer.separate_for_pipeline`：在 full 上分离一次得 `vocals_full/background_full`（UVR 保持源采样率），
  16k 单声道 `vocals/background` 由 full 版降采样得到（已有的 16k 版优先保留，不动缓存的 ASR）。
- `mix_audio`：保留床的声道数（语音单声道复制到各声道）；`_duck_envelope` 一阶 attack 50 ms / release 300 ms 包络，
  压 `MIX_DUCK_DB=-10 dB`；逐句响度匹配 = **全局偏移**（所有句 median(原片人声 RMS − TTS RMS)，不钳位）+ 逐句残差（±3 dB 钳位）；
  末尾 ffmpeg `loudnorm` 两遍到 −16 LUFS / −1 dBTP，输出 pcm_s24le。`mix_for_state` 供 runner 与 `run_vc_version.py` 共用。

**实测（test_1）**：成片音轨 48 kHz × 2ch，积分 −16.0 LUFS，真峰值 −1.0 dBTP；全局偏移 −3.66 dB
（TTS 输出比原片对白系统性响 3.7 dB），逐句残差 54 句中 28 句触及 ±3 dB 钳位（原片各句电平本身差异大，钳位按设计兜住）。

## P0-1 时长约束翻译 = 新步骤 `compact`（tts 与 fit 之间）

**问题**：翻译不知道时间槽长度；塞不下的句子只能提速到 1.60× 再截词。Sakura 不听指令，不能在翻译时约束。

**改动**：`step_compact`：合成后实测 `时长/槽`（`composer.segment_slots` 与 fit 共用同一槽公式），>1.30× 的句子按该说话人**实测秒/字**
（`speaker_sec_per_char`）算字数预算，调 `translator.compact_translation`（dolphin-mixtral:8x7b 单句改写，temperature 0）。
接受条件：更短、无假名、≥ 原文 30%、术语保留、**字符重合度 ≥ 0.3**（拒绝幻觉：实测一例编造内容的改写重合度 0.14）。
模型不会数字数（要 4 字给 6 字），所以预算只作引导：取通过检查的最短候选，第二次请求按 0.7× 预算。
改写后只重合成这些句；**取 (文本, 音频) 更短的一版**（SFT 语速逐次方差 ±40%，短文本不一定短音频），否则回退。
合成输出统一裁首尾静音（`_trim_silence_inplace`，实测有的句 1.4 s 里 0.75 s 是静音）。`text_translated_full` 保留原译。
产物 `03_compact_report.csv`、`03_zh_compact.srt`；`--no-compact` 跳过。

**实测（output_test，SFT 音色，旧 state）**：11 句 >1.30×，其中 5 句是"嗯/对吧"这类 1–3 字短句（TTS 最短时长决定，无法压）；
9 次尝试 4 次接受：2.74s→1.15s（10→6 字）、1.28s→0.65s（9→5 字）、2.61s→2.08s（18→13 字）、1.14s→1.09s（6→5 字）。

## P0-4 F0 比值门（新 `ai_movie/pitch.py`；`tts.select_best_reference/verify_clone_quality`；`scripts/auto_select_refs.py`）

**问题**：ECAPA 相似度看不见塌八度（vc-gate-result.md：塌八度参考音相似度反而更高）。F0 逻辑只在脚本里，未进流水线。

**改动**：`pitch.f0_median`（pyin 60–500 Hz，与门控文档同参数）、`pitch.gate`（输出在性别频带内且 0.8 ≤ 输出/参考 ≤ 1.25）。
`select_best_reference`：探针合成后逐候选过门，幸存者中取相似度最高，无幸存者标 `f0_warning`；
`verify_clone_quality` 增 `f0_out/f0_ref/f0_ratio/f0_ok`，不过门则 `ok=False` → 回退内置音色。
`auto_select_refs.py` 改用共享助手；探针源音频移到 `asset/vc_probe/`（不再依赖工作区）；重叠 >0.2 的窗口不作候选。

**实测（重放 output_test 的 4 条参考音探针输出）**：seg0027/seg0096（正常）3/3 通过；seg0089、S0_alt1（塌八度，输出 116–141 Hz）0/3 通过。

## P0-3 逐段 QC（新 `ai_movie/qc.py`，新步骤 `qc`）

每段汇总 asr_conf / speaker_conf / fit_ratio / overrun / tts_fallback / 克隆相似度 / 绑定轨迹 / 门控帧占比 / 超分帧 /
遮挡回退帧 / 段内切镜 / 重叠占比 / compact 改写 → PASS/WARN/FAIL + 原因。阈值 `QC_*`。
产物 `06_qc.json`、`06_qc_review.csv`（只列 WARN/FAIL，带时间码）、`06_qc_summary.txt`；有 v2 时另出 `06_qc_vc*`。
`eval_pipeline.py` 新增 F1–F4（及 C5/C6 compact、C2c F0、D8 切镜内框跳变、E2/E3 混音格式与响度）。

## P1-9 显式切镜（新 `ai_movie/shots.py`）

ffmpeg `scdet=threshold=10`，帧号 = round((t − 首帧 pts) × fps)，按视频身份缓存 `shots_cache.json`。
`faces.boxes_disjoint` 统一原来两处重复的几何启发式；`interpolate_track/interpolate_scalar` 与 `face_restore._resolve_boxes`
不跨切镜插值或延展；口型批处理与 CodeFormer 按 clip 换算局部切点。plan 新增 `cuts`、`segment_cuts`。
**实测**：test_1 15 处切镜，D8 检查（同镜头内相邻帧框跳变）= 0。

## P1-11 小脸超分路线

`gate_frames(..., min_width_sr=40)` 返回 `(gated, sr)`：[40, 80) px 的脸不再直通而进 `plan["frames_sr"]`；
`lip_sync` 批处理按 clip 决定（超分帧 ≥ 50% 锚定帧）：lanczos 放大 2×、bbox ×2、MuseTalk 后按原尺寸缩回；
超分 clip 按 6 s 重切控制内存（MuseTalk 全帧驻留，2× 帧 = 4× 内存）。
**实测**：test_2 239 帧（3 段）走超分路线；test_1 0 帧（其 [40,80) 小脸都不在被绑定的轨迹上）。

## P1-8 区域级遮挡回退（`face_restore.occlusion_gate_video(occlusion_mode=…)`）

`"frame"`（v2）整帧回退；`"region"`：原片与口型帧各解析一次，遮挡 = 下半脸内原片类别 ∈ {背景, 项链, 衣服, 头发, 帽子}
∪ (原片非人脸类 且 生成帧为唇/口)，开运算去斑、膨胀 3%S、羽化 2%S，只在该区域盖回原片；唇像素 < 0.05%·S² 持续 ≥ 6 帧才整帧回退。
**限制**：BiSeNet 把手标成皮肤，手挡嘴不会被抓到（文档写明，不隐藏）。每 clip 统计进 `state["lipsync"]["per_clip"]` 供 QC。

**A/B 实测（test_1 全片 5548 帧，`scripts/ab_occlusion.py`）**：frame 模式回退 1346 帧（其中绝大多数是无人脸帧，本就等于原片）；
region 模式回退 1261 帧、4233 帧做了区域贴回（平均权重 0.29，几乎都是刘海/头发边缘和下巴外的背景）。
对比图上两种模式肉眼无差别——这段素材没有真正的遮挡物，region 模式的额外一次解析（约 +0.1 s/帧）没有换来可见收益。
**默认保持 `frame`**，`--occlusion-mode region` 作为有头发/帽子/道具遮挡素材时的可选项。

## P1-6 三层融合 + VAE-only 消融（`patches/musetalk_fusion.patch`，`scripts/ab_fusion.py`）

见 `patches/README.md`。`--fusion laplacian`：生成帧解析出的口腔+嘴唇为 1、跨外脸 12% 渐变到 0、不越过羽化的下巴轮廓，
拉普拉斯金字塔逐频带混合；`--vae_only`：跳过 UNet，直接解码参考半 latent，量化 VAE+贴回本身的损失。

**A/B 实测（test_2 五段 × 3 变体，同一 MuseTalk 进程；`workspace/test_2/ab_fusion/`）**：

| 片段 | 脸宽 | yaw | alpha 锐度/接缝 | laplacian 锐度/接缝 | vae_only 锐度 / PSNR |
|---|---|---|---|---|---|
| 3/4 侧脸 | 126 | 40° | 0.78 / 0.98 | 0.77 / 0.98 | 0.91 / 38.0 dB |
| 多切镜大脸 | 523 | 3° | 0.93 / 0.96 | 0.93 / 0.96 | 0.98 / 40.8 dB |
| 小脸 | 64 | 44° | 0.40 / 0.93 | 0.40 / 0.94 | 0.89 / 36.3 dB |
| 正脸 | 234 | 11° | 0.56 / 0.96 | 0.57 / 0.96 | 0.90 / 39.7 dB |
| 中等侧脸 | 246 | 28° | 0.83 / 0.98 | 0.82 / 0.98 | 0.94 / 39.6 dB |

结论：**(a)** 拉普拉斯三层融合与单掩膜 alpha 在锐度和接缝上无可测差异（±0.01），默认保持 `alpha`；
**(b)** VAE-only 消融把嘴区锐度保住 0.89–0.98、PSNR 36–41 dB——256² VAE 往返本身只损失 2–10% 锐度，
**模糊几乎全部来自 UNet 生成的嘴**（正脸 0.56、小脸 0.40）。原文档"VAE 空间瓶颈"的假设不成立；
换更高分辨率 VAE 无济于事，提升上限在生成模型本身（或 CodeFormer 后处理，v2 已证明有效）。

## P1-10 A/V 偏移旋钮（`lip_sync._cut_audio_clip(offset_ms=…)`，`scripts/ab_offset.py`）

正值 = 音频相对画面延后；起点为负用 `adelay` 补零，`apad+atrim` 保证等长。`--lipsync-audio-offset-ms`，默认 0。
`ab_offset.py`：同一段视频配 −160…+160 ms 五份音频一次渲染，口腔面积序列做互相关。

**实测（test_1 47–67 s，20 s，`workspace/test_1/ab_offset/`）**：

| 偏移 | 嘴形序列相对 0 偏移渲染的滞后 | 期望 | 相关 |
|---|---|---|---|
| −160 ms | −4 帧 | −4.8 | 0.72 |
| −80 ms | −1 帧 | −2.4 | 0.84 |
| +80 ms | +2 帧 | +2.4 | 0.86 |
| +160 ms | +4 帧 | +4.8 | 0.68 |

旋钮有效且方向正确（MuseTalk 的音频上下文窗使响应略小于名义值）。但"口腔面积 vs 音频 RMS 包络"这种无模型的
绝对同步度量在这段素材上相关性只有 0.1 左右，**不足以标定零点**；零点仍由 v2 文档实测的"直通帧偏移 0 帧"支撑，
默认保持 0。要做绝对标定需要 SyncNet 类模型（本机未装），列为后续项。
