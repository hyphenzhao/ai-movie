# v3.1.0 — 性别改测原声、句子单元翻译、可疑句受限校对（2026-09-17 发布）

起点是 v3.0.0 的字幕对照评测（`Documentation/subs-eval.md`）：output_test 里"不知所云"的句子
约 15 句是 ASR 听错、约 4 句是整句被切碎、约 3 句是纯翻译错（凭空指代）。本轮针对后两类。

## 改了什么

| 改动 | 依据 |
|---|---|
| 性别（音高 + 音色分类）改在**原声**上测量，ECAPA 说话人身份仍用分离人声 | 同一男声分离后 132 Hz、原声 107 Hz；test_2 由此首次找到第二个说话人（A2a/A5 转通过） |
| ASR **仍听原声**（`--asr-audio vocals` 保留） | 同代码只换音源实测：原声中位数 0.909 / <0.70 共 14 句；分离人声 0.857 / 19 句 |
| 静音门：分离人声电平低于 −60 dBFS 的段落删除 | v3.0.0 test_2 在 −78 dBFS 静音上产出「ありがとうございました」 |
| 句子单元（`ai_movie/units.py`）：无停顿切断处、或句中连接词后合并整句翻译，再按标点/结巴分词拆回，段数不变 | 段长中位数 1.6 s，24 字上限常把句子从词中间切开（「20セ\|ンチ」「だった\|ら」） |
| 可疑句上下文校对（`sakura+qwen`），只处理日文无依据的你/他/她、疑问语气、残留假名 | 全量润色在低错误率下会把对的改错（文献与实测一致） |
| 校对守卫：删除放开、插入限于人称/语气词/标点、防删成病句 | 守卫拦下「电视剧→电影」；放开删除后采纳率 2/14 → 5~6/14 |
| 成片真峰值：编码后实测超 −1 dBTP 就按差值重编码一次 | WAV 已 −2 dBTP，但 AAC 192k 最多再抬 2 dB，v3.0.0 的 v2 成片实测 **+0.2 dBTP** |

## 两处判据本身的错误（不是成片回退）

- **D8**（同一镜头内目标框跳变）：test_2 的两次跳变正落在 S0→S1 轮次且稳定 12 帧以上，
  是性别修复让第二个说话人首次被绑定的结果。基线 0 只因当时只认出一个说话人。
  判据改为"跳开后是否弹回"（真正的缺陷是一两帧闪回）。
- **D4**（锚定帧是否真的被重绘）：原注释断言"锚定帧就是 MuseTalk 重绘的那批"，与实现不符——
  人脸计划对整段跟踪都给框，lip_sync 只处理 `sync_ranges`。test_2 的 2837 个锚定帧里只有
  1953 帧在区间内，抽样的 6 个"未变化"帧有 5 个压根没被处理过。改为只抽处理过的帧后
  test_2 28/30、另两部 30/30。

## 踩过的坑

- **校对全军覆没**：smoke 脚本把 `exclusive_engine` 日志打到 stdout，`$(...)` 把日志和模型名
  一起捕获，Ollama 返回 47 次 HTTP 400，指标等同未校对。现已改到 stderr，并在开跑前做一次
  真实往返调用验证。
- **指标噪声**：先怀疑 Sakura 不稳定，实测三次原始草稿 11/10/9，稳定；波动来自校对采纳数。
  校对改为 temperature 0 + 固定 seed + 被拒后"只删不改"重试一次。
- **Ollama 官方源下载不通**：22 GB 模型 40 次重试后仍卡在 9.6 GB（R2 连接重置），最终由用户
  自行下载安装。本机实际模型名是 `ttempvnn/HauhauCS-Qwen3.6-35B-A3B-Uncensored-...-Q4-K-M`。
