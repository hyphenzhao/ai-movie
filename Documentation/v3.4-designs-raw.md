--- DESIGN ---
## Why the existing guard misses this
`vc_guard.judge_line` (ai_movie/vc_guard.py:38) measures only voicing/pitch, and it judges only lines whose built-in baseline has >=20 confidently-voiced frames: on the current SONE-846 re-clone that is 67 of 167 converted lines in p01, 5 of 27 in p03, 24/48 in test_1. Content damage is invisible to it. Paired verify_dub data from today's runs (25 workspaces, 417 sampled lines, 299 of them converted) show 43/299 converted lines (14%) whose Whisper reading no longer resembles either the v1 reading or the intended text: language flips (「不妙啊」→"Tchau, tchau", 「没有吗？」→"Mijn oma", 「到此为止怎么样？」→"Oh, so it just, yeah"), and word drift (「把腿伸直」→「把腿先举」, 「马上拉玛尼卡」→「马上来吧你看」, 「射出来射出来」→「秀出來」). Built-in lines re-read by the same Whisper score 1.00 (p5 = 1.00), so the metric itself is stable; the loss is in the conversion.

## Fold (what "kana-folded" means here)
The dub audio is Chinese, so the fold is zh-centric; kana folding is kept as a sub-step because any kana in a forced-`zh` decode of the converted line is itself a leak signal.
`vc_guard.fold_zh(text)`:
1. `opencc.OpenCC("t2s")` (opencc-python-reimplemented 0.1.7 is already in .venv; lazy singleton, identity + one logged warning if import fails). Needed: Whisper writes traditional characters for converted timbres — 「小雞雞」 vs 「小鸡鸡」 scored 0.29 before folding, 「快點快點」 vs 「快点快点快点」 0.80 after.
2. `unicodedata.normalize("NFKC")` (full-width digits/Latin → ASCII), lowercase.
3. katakana → hiragana (same 0x60 shift as `content.fold`).
4. strip every non-word character (`re.sub(r"[^\w]|_", "")`): punctuation, spaces, 「」…——.
`vc_guard.text_sim(a, b)` = `difflib.SequenceMatcher(None, fold_zh(a), fold_zh(b), autojunk=False).ratio()`; 0.0 when either side folds to empty. Same family as `content.classify` (CONTENT_AGREE_MIN) and `eval_against_subs.ratio`, so numbers are comparable across the repo.

## Judge (pure, offline-testable)
`vc_guard.judge_content(conv_text, v1_text, want, *, min_chars=VC_DRIFT_MIN_CHARS, baseline_min=VC_DRIFT_BASELINE_MIN, min_sim=VC_DRIFT_MIN_SIM) -> {"judged", "ok", "reason", "score", "baseline", "heard_conv", "heard_v1"}`:
- `baseline = text_sim(v1_text, want)`. Not judged (`judged=False`) when `len(fold_zh(want)) < min_chars` or `baseline < baseline_min`: if Whisper cannot hear the *built-in* line (moans 「啊啊啊」, 「哥哥……」 heard as "Фига!"), it cannot judge its conversion — the same principle as VC_GUARD_MIN_BASE_FRAMES.
- Hard rejects that need no length: `script_flip` when the converted decode contains no CJK while the v1 decode does (catches "Shut up"/"Bye-bye" even on 2-char lines), `kana_leak` when conv has >= VC_DRIFT_KANA_LEAK kana chars and v1 has none.
- `score = max(text_sim(conv, v1_text), text_sim(conv, want))`. Anchoring on the v1 transcription (as specified) calibrates out Whisper's own error on TTS audio; taking the max with the intended text `text_translated` removes the false rejections where Whisper mis-heard v1 but heard the conversion correctly (p02 #5: v1 read as 「中文字幕提供」, conversion 「标的风格」 vs want 「啾的风格」 = 0.75). Reject with reason `drift_{score:.2f}` when `score < min_sim`.

## Thresholds and their justification (from the 417-row paired sample, folded as above)
- VC_DRIFT_MIN_CHARS = 3: on 1–2 char strings the ratio is quantised to {0, 0.5, 0.67, 1}; such lines are almost always converted inside a chunk anyway, where the chunk text is judged (below).
- VC_DRIFT_BASELINE_MIN = 0.6: keeps 240/299 converted lines judgeable (vs 67/167 for the pitch guard); the excluded ones are nonlexical or mis-heard baselines, not conversions.
- VC_DRIFT_MIN_SIM = 0.5: rejects 15/240 judgeable lines (6%); ~11 are audibly wrong content (the language flips and the word drifts above), ~4 are Whisper homophone choices on intact audio (「变得」/「电的」, 「疼得」/「腾力」). At 0.6 the sample adds 6 rejections that are almost all homophones (「填一填」/「舔一舔」, 「全圆」/「全员」, 「周围」/「稍微」) — false. So 0.5 now; 0.6 becomes safe only with a pinyin fold (pypinyin is NOT installed; ~1.5 MB via the campus proxy — ask before fetching; the fold is a single function so it is a drop-in later).
- VC_DRIFT_KANA_LEAK = 2 (one kana can be a Whisper artefact on 「嗯」).
- Existing VC_GUARD_MAX_REJECT = 0.3 keeps its role; note its denominator grows from ~40% to ~85% of converted lines because content can be judged on lines pitch cannot.

## Unit of judgement = unit of conversion
`tts.run_vc_conversion` converts short neighbouring lines as one utterance (`_vc_chunks`, `_write_vc_chunk`, `_split_vc_chunk`; tts.py:1030-1090) and the guard already drops a chunk whole. Chunk members are therefore judged at chunk level: transcribe the converted chunk output (`seg_{1000000+first+1:04d}.wav`, the worker's output for the synthetic id) against the concatenated built-in source (`chunks/chunk_XXXX_YYYY.wav`), with `want = "。".join(text_translated of members)` — longer text, fewer decodes (p01: 85 chunks + 24 singles instead of 167 lines), and the verdict maps onto the existing drop rule with no dilution of a single spliced-in built-in line. Singles (>= 0.7 s, not chunkable) are judged per line: converted `items[i]["audio"]` vs `v1_segs[i]["audio_fit"]`. To make the chunk paths available, `run_vc_conversion` adds `"chunk_src": layout["path"], "chunk_out": r["audio"]` to each chunk member's item (tts.py:1083, 3 lines; `run_vc_conversion` is not in any STEP_CODE).

## Transcription: one model load per run_vc_version process, GPU, batched, outside the CosyVoice worker
`run_isolated_synthesis` (tts.py:597) spawns `tts_worker.py` per call and kills it before returning, so when `guard_lines` runs the GPU holds nothing but the evicted-Ollama headroom (`free_gpu_for_local_work()` at tts.py:988). Whisper therefore loads in the run_vc_version main process (same .venv that runs the ASR stage's in-process `whisper.load_model(...).to("cuda")`, asr.py:542), never inside the worker (transformers 4.51.3 pin, main-thread CosyVoice).
New in ai_movie/asr.py (new functions only; nothing hashed by STEP_CODE["asr"] is touched):
- `class WhisperClips(model_size=VC_DRIFT_WHISPER_MODEL, cache: Path|None)`: lazy `whisper.load_model(model_size, device="cuda")` on first use (large-v3.pt is already in ~/.cache/whisper; HF_HUB_OFFLINE-safe); `transcribe(paths) -> {path: {"text","avg_logprob","no_speech_prob","compression_ratio"}}`: dedupe, skip cache hits (key `f"{path}|{size}|{mtime_ns}"`, JSON file `synthesized_vc/_drift_transcripts.json` — v1 clips are decoded once and reused across retry attempts and re-runs), then `whisper.load_audio` → `pad_or_trim` → `log_mel_spectrogram(n_mels=model.dims.n_mels)` stacked into batches of VC_DRIFT_BATCH and decoded with `whisper.decode(model, mel, DecodingOptions(task="transcribe", language="zh", temperature=0.0, beam_size=VC_DRIFT_BEAM, without_timestamps=True, fp16=True))` (verified: `whisper.decode` accepts `(*, n_mels, 3000)` and returns a list of DecodingResult in openai-whisper 20250625). Results with `compression_ratio > 2.4` (greedy loops) are re-decoded individually with temperatures (0.2, 0.4) like `_transcribe_sweep`. `close()` deletes the model and calls `torch.cuda.empty_cache()`.
- Forced `language="zh"` is essential: verify_dub's auto-ID labels converted clips pt/en/ru/ko; the judge must measure content, not language ID. Under forced zh a genuinely English output still decodes to non-matching text (and often no CJK → script_flip).

## Integration

### A. `ai_movie/units.py` — broaden `is_nonlexical` (l.279–317)
```python

_EXCLAIM = re.compile(r"^(?:うわ|きや|ぎや|ひや)(?=[あいうえおんはひふへほ]|$)")   # うわー / きゃー: a scream
_HELD = re.compile(r"([あいうえおんはひふへほ])(?:\1|[ー〜～])*|[ー〜～]{2,}")  # one vowel + its elongation marks

def _kana_marked(ja: str) -> str:
    """_kana_base but keeps ー 〜 ～ (drops っ): あーーー is a held あ, not one character."""
    t = "".join(chr(ord(c) - 0x60) if "ァ" <= c <= "ヶ" else c for c in (ja or "")).translate(_SMALL)
    return "".join(c for c in t if "ぁ" <= c <= "ゖ" or "一" <= c <= "鿿" or c.isalnum() or c in "〜～").replace("っ", "")

def is_nonlexical(ja: str, *, held_run: bool = True) -> bool:
    base = _kana_base(ja)
    if not base: return True
    if base in _NONLEX_WORDS: return False          # whitelist first: いい / ええ / はーい stay content
    base = _EXCLAIM.sub("", base)                   # うわ/きゃ + vowel run = scream
    if not base or all(c in _NONLEX_BASE for c in base): return True
    for n in (1, 2):                                # repeated 1–2-kana sound (unchanged)
        if len(base) >= 2 * n and len(base) % n == 0 and base == base[:n] * (len(base) // n):
            return all(c in _NONLEX_SOUND for c in base[:n])
    if not held_run: return False
    marked = _kana_marked(ja)                       # sustained sound dominates: あああああ大 / ぁ×16とりあえず / ー×200おわり
    longest = max((len(m.group(0)) for m in _HELD.finditer(marked)), default=0)
    return longest >= CONTENT_HELD_RUN_MIN and longest >= CONTENT_HELD_RUN_FRAC * len(marked)
```

## 1. L5 — crossfade at switch boundaries

Principle: the fade lives ONLY on generated frames. Frames the gate/plan says must be original stay 100 % original (never paint a generated mouth onto an occluder or a profile face); the generated mouth fades in over the first F generated frames of a run and out over the last F. No frame is added or dropped — a blend is per-frame between `ow[i]` and `lw[i]` of the SAME index, so the clip's frame count and `_fit_clip_to_duration`'s `-vframes` are untouched (memory: assembly frame loss).

1a. New pure helper `ai_movie/faces.py::switch_fade_weights(use_orig: Sequence[bool], fade: int, cuts: Iterable[int] = ()) -> np.ndarray[float32]` (numpy only, next to `_median_filter_runs`/`gate_frames` so tests import no torch):
```
w = np.asarray(use_orig, float32)            # 1 = show original, 0 = show generated
if fade <= 0: return w
for each maximal run of 0s [i, j):
    L = j - i
    f_in  = 0 if i in cuts else min(fade, L // 2)          # a cut already hides the switch
    f_out = 0 if j in cuts else min(fade, L - f_in)        # f_in + f_out <= L, never overlap
    w[i + t]     = (f_in  - t) / (f_in  + 1)   for t in range(f_in)    # 4/5,3/5,2/5,1/5 at fade=4
    w[j - 1 - t] = (f_out - t) / (f_out + 1)   for t in range(f_out)
return w
```
Clip edges (i == 0, j == n) fade too (the neighbouring gap clip is original; harmless and slightly better). A generated run shorter than 2·fade (only possible between two occlusion runs — the plan gate is median-filtered over FACE_GATE_SMOOTH=15) is low-passed instead of flickering: that is wanted.

1b. `face_restore.occlusion_gate_video` gets two keyword args: `fade_frames: int | None = None` (None → `config.LIPSYNC_SWITCH_FADE_FRAMES`) and `anchored: set[int] | None = None` (clip-local frames MuseTalk was asked to paint; None = all). Per chunk after the existing `revert` pass:
```
use_orig[i] = revert[i] or (anchored is not None and i not in anchored)
flags = held_flags + use_orig                       # ≤ fade frames deferred from the previous chunk
if not last_chunk: flags += [flags[-1]] * fade      # "run continues": no fade-out computed at a chunk edge
w = switch_fade_weights(flags, fade, local_cuts(cuts, base - len(held), len(flags)))
frames = held + zip(ow, lw); write frames[: len(frames) - (0 if last_chunk else fade)]; hold the rest
out[i] = ow if w==1 else lw if w==0 else clip(ow*w + lw*(1-w))   (float32 blend, uint8 out)
```
The hold-back guarantees a frame's weights are final before it is written (fade-out depends on run ends ≤ i+fade). `processed` and `total` keep their meaning; assert `written == total` at the end and log it. Unanchored frames are bit-identical in ow/lw (MuseTalk passthrough) so the plan-gate fade is automatically one-sided on the generated side. Region mode (`OCCLUSION_MODE="region"`) composites into `lw[i]` before the blend, so it composes correctly. If `face_parser_available()` is False the gate still just copies (no fade) — documented.
